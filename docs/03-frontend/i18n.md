# Internacionalización (i18n)

> Política de strings de UI y guía para añadir/modificar claves usando **vue-i18n**.

---

## Estado actual

- **Plugin**: `vue-i18n@9.14` instalado y configurado en `CourselyLabs-front/src/main.ts`.
- **Locale activo**: `es` (castellano). Es el único idioma del proyecto hoy. La infraestructura está lista para añadir más en el futuro.
- **Diccionario**: `CourselyLabs-front/src/i18n/locales/es.json` (~250 claves).
- **Migración a `t()`**: parcial. Solo 3 componentes la usan hoy:
  - `layouts/InstructorLayout.vue`
  - `views/instructor/GradingDashboard.vue`
  - `components/AssessmentEditor.vue`

El resto de la app sigue con strings inline en castellano (con ortografía corregida tras un sweep masivo). La migración progresiva del resto se hace a demanda.

## Política

### Reglas obligatorias

1. **Todo string visible al usuario va en castellano correcto** — con tildes, signos de apertura `¿…?`, `¡…!`, comillas `«…»`.
2. **Nuevos componentes usan `t()` desde el primer commit**. No se acepta hardcodear strings nuevos.
3. **Las URLs no llevan tildes**. `/cursos/:slug/leccion/:id`, no `/lección/`. Las rutas son ASCII.
4. **Los identificadores en código siguen en inglés**: `lessonId`, `currentQuestion`, `LessonBlock`. Solo los strings UI van en castellano.
5. **Nada de mezclar idiomas**: si un componente está en inglés (vestigio histórico), traduce el archivo entero, no parches puntuales.

### Cuándo migrar a `t()`

- ✅ Componente nuevo → `t()` desde el inicio.
- ✅ Componente que tocas para añadir/cambiar features → migra los strings que toques en ese mismo PR.
- ⚠️ Componente que solo lees → no es obligatorio migrarlo "por estar de paso", pero sí corrige cualquier falta de tilde que veas.
- ❌ No abrir un PR que solo migra strings sin cambio funcional, salvo en el sweep planificado para la rama de unificación de docs/i18n.

## Estructura de `es.json`

Organizado por **dominio**, no por componente. Esto permite reutilizar claves entre componentes que comparten vocabulario.

```json
{
  "common":     { "save": "...", "cancel": "...", "delete": "...", ... },
  "app":        { "title": "CourselyLabs", ... },
  "nav":        { "home": "...", "courses": "...", ... },
  "auth":       { "login": "...", "email": "...", ... },
  "home":       { "heroTitle": "...", ... },
  "courses":    { "pageTitle": "...", "filterCategory": "...", ... },
  "course":     { "tabContent": "...", "level": { ... }, "status": { ... } },
  "lesson":     { "noContent": "...", "markCompleted": "...", ... },
  "assessment": {
    "type":     { "quiz": "...", "project": "...", "openText": "..." },
    "intro":    { ... },
    "editor":   { ... },
    "quiz":     { ... },
    "results":  { ... }
  },
  "instructor": {
    "wizard":   { ... },
    "grading":  { ... }
  },
  "admin":      { ... },
  "premium":    { ... },
  "review":     { ... },
  "notFound":   { ... },
  "footer":     { ... }
}
```

**Convención de nombres**:
- `camelCase` (no `snake_case` ni `kebab-case`).
- Verbos en infinitivo o imperativo para acciones (`save`, `cancel`, `markCompleted`).
- Pares `xxx` / `xxxOk` / `xxxError` para acciones que pueden notificar (ej. `delete` → label, `deletedOk` → notify positivo, `deleteError` → notify negativo).
- Sufijos `_Title`, `_Body`, `_Cta` para diálogos (`deleteConfirmTitle`, `deleteConfirmBody`).

## Cómo usar `t()` en componentes

### Setup en un `.vue` con `<script setup>`

```vue
<script setup lang="ts">
import { useI18n } from 'vue-i18n'

const { t } = useI18n()
</script>

<template>
  <q-btn :label="t('common.save')" @click="save" />
  <p>{{ t('lesson.noContent') }}</p>
</template>
```

### Interpolación de variables

`es.json`:
```json
"course": {
  "byInstructor": "Por {name}"
}
```

Vue:
```vue
<p>{{ t('course.byInstructor', { name: instructor.name }) }}</p>
```

### Pluralización

Vue I18n usa `|` como separador de formas plurales: **cero | uno | varios** (orden de la documentación oficial).

`es.json`:
```json
"lesson": {
  "downloadCount": "{count} descargas | {count} descarga | {count} descargas"
}
```

Vue (usa `t` con número como segundo argumento, **no** `tc` que es legacy):
```vue
<span>{{ t('lesson.downloadCount', count) }}</span>
```

### Notificaciones (Quasar `$q.notify`)

```ts
import { useI18n } from 'vue-i18n'
const { t } = useI18n()

$q.notify({
  type: 'positive',
  message: t('common.savedOk'),
  position: 'bottom-right',
})
```

## Cómo añadir una clave nueva

### 1. Identifica el dominio

¿Es genérica (botón "Cancelar")? → `common`. ¿Es de un dominio (editor de evaluaciones)? → `assessment.editor.xxx`.

Mira primero si **ya existe**. Reutilizar es mejor que duplicar.

### 2. Añade la clave a `es.json`

Mantén orden alfabético dentro de cada bloque cuando sea razonable. Para diálogos, agrupa `Title`/`Body` juntos.

```json
"assessment": {
  "editor": {
    "deleteAssessment": "Eliminar evaluación",
    "deleteConfirmTitle": "Eliminar evaluación",
    "deleteConfirmBody": "¿Eliminar la evaluación configurada en este bloque? El bloque se mantendrá y podrás reconfigurarla.",
    "deletedOk": "Evaluación eliminada",
    "deleteError": "Error al eliminar la evaluación"
  }
}
```

### 3. Úsala con `t('ruta.completa.de.la.clave')`

```vue
<q-btn :label="t('assessment.editor.deleteAssessment')" @click="confirmDelete" />
```

### 4. Verifica con `vue-tsc`

`npm run type-check` no detecta strings de `t()` mal escritos en runtime, pero sí detecta otros problemas. Si añades muchas claves, conviene ejecutarlo periódicamente.

> Si quieres detección estática de claves, hay plugins como `@intlify/unplugin-vue-i18n` que emiten warnings de claves inexistentes en build. **No están instalados todavía**. Considera añadirlos cuando se complete la migración.

## Cómo migrar un componente existente

Workflow recomendado:

1. **Lee el archivo entero** y haz inventario de strings.
2. **Identifica las claves**: agrupa las que ya existen en `common.*` o en el dominio. Crea las que faltan.
3. **Añade `useI18n()`** al setup.
4. **Reemplaza los strings**: en template usa `{{ t('clave') }}` o `:label="t('clave')"`. En script usa `t('clave')`.
5. **Casos especiales**:
   - Strings dinámicos con interpolación: usa la sintaxis `{ var }` en el JSON.
   - Strings con HTML embebido: ten cuidado, `t()` devuelve string plano. Si necesitas HTML, considera dividir en piezas o usar `i18n-t` (component, no `t()` función).
   - Strings dentro de objetos `options` o `tabs`: ten cuidado de no convertirlos en computed que se evalúen una sola vez si dependen del idioma (no aplica todavía con un solo locale, pero anticipa).
6. **Verifica el build**: `npm run build`.
7. **Prueba manualmente**: navega al componente y revisa que no quede ningún string inline ni roto.

### Ejemplo before/after

**Antes**:
```vue
<q-btn label="Guardar configuración" @click="save" />
<q-banner v-if="error">Error al guardar</q-banner>
```

**Después** (`es.json`):
```json
"assessment": {
  "editor": {
    "saveConfig": "Guardar configuración",
    "configSaveError": "Error al guardar la configuración"
  }
}
```

```vue
<script setup>
import { useI18n } from 'vue-i18n'
const { t } = useI18n()
</script>

<template>
  <q-btn :label="t('assessment.editor.saveConfig')" @click="save" />
  <q-banner v-if="error">{{ t('assessment.editor.configSaveError') }}</q-banner>
</template>
```

## Sweep ortográfico (histórico)

Cuando se introdujo la infraestructura i18n se hizo además un **sweep masivo** de strings inline castellanos para corregir tildes y faltas. Aplicado con scripts `sed` con word-boundaries y verificado con `vue-tsc` después.

Patrones aplicados (resumen):

- **Sustantivos `-ción/-sión`**: `evaluación`, `configuración`, `información`, `descripción`, `revisión`, `verificación`, `inscripción`, `corrección`, `administración`, `publicación`, `suscripción`, `decisión`, `calificación`, `creación`, `edición`, `validación`, `explicación`, `sección`, `acción`, `valoración`, `actualización`, `función`, `opción`, `lección`, `versión`, `puntuación`, `duración`, `presentación`, `comunicación`, `motivación`, `documentación`, `selección`, `televisión`, `visión`, `misión`…
- **Adjetivos**: `público/pública`, `máximo/mínimo`, `automático`, `temático`, `académico`, `típico`, `histórico`, `científico`, `rápido`, `último`, `físico`, `lógico`, `cómodo`, `próximo`…
- **Verbos en futuro/condicional**: `será/serán`, `estará/estarán`, `podrá/podrán`, `tendrá/tendrán`, `deberá/deberás`, `verá/verás`, `mantendrás`, `harán`, `comenzará`, `necesitarás`, `encontrará`…
- **Adverbios**: `también`, `después`, `aún`, `aquí`, `así`, `además`, `automáticamente`, `rápidamente`, `atrás`…
- **Geo y comunes**: `España`, `América`, `México`, `país/países`, `través`, `catálogo`, `útil`, `fácil`, `difícil`, `índice`, `límite`, `título`, `página`, `categoría`, `botón`, `envío`, `línea`, `época`, `ámbito`, `éxito`, `examen/exámenes`, `ningún`, `algún`, `común`…
- **Demostrativos protegidos**: `está` (verbo) vs `esta` (demostrativo) tratados manualmente para no confundirlos.
- **Puntuación**: `Sí` con tilde como afirmación, `¿…?` `¡…!` añadidos en preguntas/exclamaciones, `«…»` en lugar de `"..."` para citas en español.

> **Importante**: este sweep también aplicó al backend en `CourselyLabs-back/src/main/java`, corrigiendo mensajes de excepción y notificaciones a castellano correcto.

## Cuando llegue otro idioma

Cuando se decida añadir, por ejemplo, inglés:

1. Crea `src/i18n/locales/en.json` con la misma estructura que `es.json`.
2. En `src/i18n/index.ts`, añade `en` al `messages`.
3. Añade un selector de idioma en la UI (probablemente en `AppHeader.vue`).
4. Persiste la elección en `localStorage` (clave `coursely-locale`).
5. Configura `axios` para enviar `Accept-Language` con el locale activo (útil si el backend internacionaliza errores).

El backend hoy devuelve mensajes en castellano hardcoded. Si se quieren mensajes localizados desde el backend, habrá que introducir `MessageSource` de Spring con `messages_es.properties` / `messages_en.properties`.

## Errores comunes y cómo evitarlos

| Error | Síntoma | Solución |
|---|---|---|
| Olvidar `useI18n()` en setup | `t is not defined` en runtime | Añadir el import |
| Clave inexistente | El texto literal `assessment.editor.xxx` aparece en pantalla | Verificar que la clave está en `es.json` y bien escrita |
| Variable de interpolación no pasada | `{name}` aparece literal | Pasar el segundo argumento: `t('xxx', { name: '...' })` |
| Pluralización con `tc` | Warning: `tc is deprecated` | Usar `t(key, count)` directamente en v9 |
| String con HTML pasado a `t()` | El HTML aparece escapado | Usar `<i18n-t>` component o `v-html` con cuidado |
| Romper una URL al añadir tilde a un identificador | 404 al navegar | Las URLs son ASCII; nunca poner tildes en `path:` de routes |
